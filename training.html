XSS Training

Understand what XSS is, when to use which payload, and why.

Theory + real-world examples

1. What is XSS?

Cross-Site Scripting (XSS) is a vulnerability that lets an attacker inject malicious JavaScript into a web page, so the victim's browser executes it in the context of the vulnerable origin.

Impact: steal cookies/sessions, keylogging, phishing, account takeover, perform actions on behalf of the user.

Root cause: the app takes user-controlled data (URL, form, headers, storage...) and renders it directly into HTML/JS without escaping or sanitizing.

2. Types of XSS

  • Reflected XSS: payload travels through the request (URL/form) and is returned immediately in the response. Not stored.
  • Stored XSS: payload is saved (DB/storage) and shown to many users later.
  • DOM-Based XSS: the flaw lives in client-side JavaScript (sinks like innerHTML, eval, document.write...), no server involved.

3. When to use which payload? (by injection context)

The most important rule: the payload must match the "context" where the data is inserted. Same sink, different position → different payload.

Context 1: HTML Body

Data is inserted directly into the HTML body (innerHTML, document.write, template).

<div>Hello <script>alert(1)</script></div> <div>Hello <img src=x onerror=alert(1)></div>

Use: <script>alert(1)</script> or <img src=x onerror=alert(1)>

Don't use: alert(1) directly (browser treats it as text, won't execute).

Context 2: HTML Attribute

Data is inserted into an attribute value (value, src, href, onclick...). You must "break out" of the attribute and tag first.

<input value="USER_INPUT"> <a href="USER_INPUT">click</a>

Breakout payloads:

" onerror="alert(0) ' onmouseover='alert(0) " autofocus onfocus="alert(0)

Use: " onerror="alert(0) (inside src/href) or " autofocus onfocus="alert(0)

Don't use: <script>alert(1)</script> (treated as attribute value, not parsed as a tag).

Context 3: JavaScript Code

Data is inserted inside a <script> block (JS variable, string). You must escape out of the JS string/context.

var name = 'USER_INPUT'; var x = USER_INPUT;

Breakout payloads:

';alert(0)// ";alert(0)// ');alert(0)// alert(0) // when input is eval()'d directly

Use: alert(0) directly when the sink is eval(userInput) / setTimeout(userInput).

Use: ';alert(0)// when input sits inside a JS string.

Don't use: <script>alert(1)</script> (already inside JS, tags won't be parsed).

Context 4: URL / href / src

Data is inserted into a URL (location.href, href attribute, src). You can use a pseudo-protocol.

<a href="USER_INPUT">click</a> location.href = USER_INPUT;

Use: javascript:alert(0) or javascript:alert(document.cookie)

Don't use: alert(0) (not a valid URL).

5. Practice tips

  • Always check View Source / DevTools to identify the injection context before picking a payload.
  • Start with minimal payloads: alert(1), alert(document.domain), alert(document.cookie).
  • If filtered, try bypasses: change case, use onerror, onload, onfocus, svg, body.
  • Prevention: use textContent instead of innerHTML, escape HTML entities, CSP, validate input.
